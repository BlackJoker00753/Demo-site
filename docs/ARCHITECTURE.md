# Архитектура Horologium

## 1. Идея продукта

Энциклопедия часов в формате интерактивной презентации. Путь пользователя:

```
Глобус ──▶ Страна (спутниковая карта, границы, бренды на карте)
        ──▶ Бренд (история, средняя цена и диапазон, каталог с вкладками)
        ──▶ Модель (скролл-история в стиле Apple, поколения, механизм,
                    усложнения, цена, разборка настоящего механизма по скроллу)
```

**Принцип «только настоящие фотографии».** Во всех местах, где пользователь видит часы
(карточки, шапки бренда и модели, список брендов страны), показываются только реальные
снимки под свободными лицензиями с автором и лицензией. Сгенерированное 3D осталось только
как дополнительный режим «3D-разборка» в конце страницы модели. Основной режим разборки
собран из фотографий настоящих деталей (см. раздел 9).

Дополнительно: поиск (с транслитерацией «ролекс» → Rolex), словарь усложнений, страницы калибров.

## 2. Стек и почему именно он

| Слой | Выбор | Обоснование |
|---|---|---|
| Бэкенд | **FastAPI** (Python 3.11+) | Рекомендован заказчиком. Типизированный контракт через Pydantic, автодокументация `/api/docs`, быстрый. |
| ORM / БД | **SQLAlchemy 2.0 + SQLite** | Каталог в сотни записей, только чтение. SQLite не требует сервера, файл собирается за доли секунды. |
| Контент | **YAML + Pydantic-схема** | Редакторам (и ИИ-агентам) удобно писать тексты в YAML. Схема ловит опечатки до того, как они попадут на сайт. |
| Фронтенд | **Vanilla ES-модули без сборщика** | Проект запускается одной командой `uv run horologium serve`, без Node.js. Библиотеки вендорены в `frontend/vendor/`. |
| 3D | **Three.js** | Глобус со спутниковой текстурой; процедурная 3D-схема часов (дополнительный режим разборки) с HDRI-светом и ambient occlusion (GTAO). |
| Фото | **Wikimedia Commons, Openverse** | Единственные крупные источники снимков часов под CC0, PD, CC BY, CC BY-SA. Пресс-фото брендов не используются из-за прав. |
| Анимации | **GSAP + ScrollTrigger, Lenis** | Скролл-сцены в стиле Apple, плавная прокрутка, переходы между страницами. |

```

  web/spa.py                 раздача фронтенда + SSR мета-тегов

  pricing/refresh.py         CLI обновления цен и отчёт о свежести
  cli.py                     `horologium serve|check|build-db|prices`
  main.py                    create_app()

  assets/photos/<slug>/<n>-{480,960,1600}.jpg   фото моделей в трёх размерах

  photos.py                  поиск фото (Commons + Openverse), контактные листы, выбор, кадрирование
  pick_batch.py              пакетный выбор фото из списка «slug|индекс|подпись|фокус|ctx|кадр»
```

## 4. Поток данных

```
content/*.yaml ──(loader + schema)──▶ ContentBundle ──(db/build)──▶ SQLite
                                                                     │
          pricing/refresh ──▶ price_snapshots (переживает пересборку) ┘
                                                                     │
                     services/catalog ──▶ api/routes (/api/v1) ──▶ фронтенд
```

- При старте сервера `ensure_database()` сравнивает SHA-256 всего контента с `meta.content_digest`. Если контент изменился, каталог пересобирается автоматически.
- Таблица `price_snapshots` не удаляется при пересборке. Если обновлялка нашла цену новее, чем дата `checked` в YAML, в каталог попадает свежая цена.

## 5. API (v1)

| Метод | Описание |
|---|---|
| `GET /api/v1/stats` | счётчики каталога |
| `GET /api/v1/countries` | страны со статистикой цен |
| `GET /api/v1/countries/{slug}` | страна + бренды (средняя цена, мин/макс) |
| `GET /api/v1/brands?country=` | бренды |
| `GET /api/v1/brands/{slug}` | бренд, история, фасеты-вкладки, модели |
| `GET /api/v1/watches?brand=&country=&type=&complication=&sort=` | фильтр моделей |
| `GET /api/v1/watches/{slug}` | модель целиком: механизм, история, цена, соседи |
| `GET /api/v1/complications[/{slug}]` | словарь усложнений |
| `GET /api/v1/movements/{slug}` | калибр и часы с ним |
| `GET /api/v1/search?q=` | поиск |
| `GET /api/v1/part-photos` | фото деталей и снимки разобранных калибров с точками (`hotspots`) |
| `GET /api/v1/credits` | авторы и лицензии всех фотографий |

Фото в ответах: `WatchCard.photo` (своё фото модели, иначе снимок родственной модели с
`context: true`), `WatchDetail.photos` (все, сначала свои), `BrandCard.hero_photo`.

Фасеты бренда: `all`, `mechanical` (автомат + ручной), типы механизмов (`automatic`, `manual`, `quartz`, `solar`, `spring_drive`, `smart`…), затем усложнения с `tab: true`.

## 6. Цены

- Каждая цена хранит `usd`, `kind` (`msrp` официальная розница / `market` рынок / `estimate` оценка), `source`, `url`, `checked`.
- Основной путь: исследование официальных прайс-листов (сайт бренда через реальный браузер, т.к. многие сайты закрыты антиботом для скриптов) и авторитетных сводок. Дата проверки указывается в YAML.
- Автоматическое обновление: `horologium prices refresh` проходит по моделям с `price.url`, пробует провайдеров (`JsonLdProvider`, `MetaTagProvider`), пересчитывает валюту по курсам ЕЦБ и пишет снимок. Сайты с Cloudflare-челленджем (например, Jomashop) честно пропускаются.
- Средняя цена бренда и диапазон (мин, макс) считаются по моделям бренда в атласе (`services/catalog.price_stats`).

## 7. SEO

SPA-шелл `frontend/index.html` содержит маркеры `<!--SSR:TITLE-->` и `<!--SSR:DESCRIPTION-->`, которые сервер заменяет на заголовок и описание страны, бренда или модели. Ссылки в мессенджерах и поисковиках получают правильные превью.

## 8. Тесты

`uv run pytest` собирает временную базу из настоящего контента и проверяет: валидность и хронологию контента, адекватность цен, агрегаты, фильтры, поиск, 404, SSR-мета.

## 9. Фотографии и разборка из настоящих деталей

**Фото моделей.** `scripts/photos.py candidates` ищет по запросам из `photo_queries.yaml` в Commons
(полнотекстовый поиск и файлы из найденных категорий) и в Openverse (только CC, без PDM: на Flickr
им часто помечают перезалитые пресс-фото). Кандидаты ранжируются по совпадению названия модели и
референса, здания и открытки уходят вниз. Человек или ИИ смотрит контактный лист и выбирает кадры
(`pick`, `pick_batch.py`). Каждое фото хранит автора, лицензию, ссылку на исходник и подпись, если на
снимке другая версия модели. Снимок родственной модели помечается `context: true`: он виден в ленте
«Вживую», в карточке с пометкой «Похожая модель» и никогда не выдаётся за саму модель.
Если снимков нет совсем, карточка и шапка показывают типографскую заглушку, а не 3D.

**Фото деталей.** `part_photos.yaml`: для каждого ключа детали из `frontend/js/watch3d/parts-info.js`
настоящий макроснимок (баланс, анкерная вилка, барабан, камертон кварца…). Показывается в карточке детали.

**Разборка из фотографий** (`scripts/cutouts.py` → `frontend/js/ui/photo-explode.js`):

```
снимок «все детали на столе» ──сегментация──▶ спрайты деталей (webp с прозрачностью)
                                              + manifest.json: для каждой детали
                                                key, z (слой), from (место в собранных часах),
                                                to (место в разборке), fade (корпус растворяется)
```

- `eta-955`: кварцевый калибр ETA-ESA 955.412 (Commons, CC0). Фон светлый, детали отделяются в
  пространстве Lab от локально оценённого фона; белое кольцо даты совпадает с фоном по цвету и
  задаётся геометрически. Разобранная раскладка повторяет исходный снимок.
- `prim`: музейный набор механических часов Prim (Commons, CC BY-SA 3.0). Детали на чёрном бархате
  рядом с подписями и поролоном, поэтому каждая выбирается точкой-семенем; раскладка задана вручную,
  собранное состояние начинается с настоящих часов.
- По скроллу (ScrollTrigger) и ползунку детали снимаются слоями сверху вниз, как у часовщика,
  камера отъезжает от крупного плана, в конце появляются кликабельные точки.
- Режим выбирается по типу механизма модели: кварц, солнечные, смарт → `eta-955`, остальное → `prim`.
  Это не механизм именно этой модели, а настоящий представитель того же типа; так и подписано.

## 10. Разборка до детали (teardown)

```
content/teardown/{families,watches}/*.yaml ──tasks──▶ docs/TEARDOWN_GEMINI_TASK.md
        ──generate (Gemini 3 Pro Image, 4K, референсы: официальные фото)──▶ teardown_src/…/<лист>.png
        ──build (сегментация, порядок чтения/клетки сетки, масштаб по мм, атлас, слои)──▶
        frontend/assets/teardown/<slug>/{atlas-N.webp, assembled_front.webp, manifest.json}
        ──▶ frontend/js/ui/teardown.js (WebGL, InstancedMesh на страницу атласа)
```

- Координаты: ось Y сцены = ось часов (0 = середина), 12 часов = −Z, 3 часа = +X, единица = 1 мм.
- `manifest.parts[]`: `key` (описание в parts-info.js), `name`, `w/h` (мм), `z` (слой), `page` + `uv`
  (атлас), `at` (положение в собранных часах), `ex` (в разборке), `y` (высота слоя в разборке).
- Слои по ключам (`LAYERS` в teardown.py): от задней крышки (0) к стеклу (10); браслет раскладывается
  рядами вдоль оси 12–6 часов, головка и кнопки сбоку на 3 часах.
- `tray`, `tray_sq`, `tray_tall`: положение на лотке часовщика в трёх пропорциях (1,75, 1,1, 0,72);
  плеер выбирает ближайшую к свободной части холста.
- Плеер (`t` от 0 до 1): до 0,52 слои расходятся вдоль оси, камера наклоняется до 55°; дальше детали
  группами ложатся на лоток, камера возвращается в вид сверху. Кадр подбирается проекцией точек в
  камеру; `setInset(left, top, bottom)` исключает зоны под текстом, вкладками и ползунком
  (`setViewOffset` сдвигает центр). Инстансы отсортированы по высоте, чтобы стекло не закрывало
  циферблат по глубине.
