# Архитектура Horologium

## 1. Идея продукта

Энциклопедия часов в формате интерактивной презентации. Путь пользователя:

```
Глобус ──▶ Страна (спутниковая карта, границы, бренды на карте)
        ──▶ Бренд (история, средняя цена и диапазон, каталог с вкладками)
        ──▶ Модель (скролл-история в стиле Apple, поколения, механизм,
                    усложнения, цена, 3D-разборка часов ползунком)
```

Дополнительно: поиск (с транслитерацией «ролекс» → Rolex), словарь усложнений, страницы калибров.

## 2. Стек и почему именно он

| Слой | Выбор | Обоснование |
|---|---|---|
| Бэкенд | **FastAPI** (Python 3.11+) | Рекомендован заказчиком. Типизированный контракт через Pydantic, автодокументация `/api/docs`, быстрый. |
| ORM / БД | **SQLAlchemy 2.0 + SQLite** | Каталог в сотни записей, только чтение. SQLite не требует сервера, файл собирается за доли секунды. |
| Контент | **YAML + Pydantic-схема** | Редакторам (и ИИ-агентам) удобно писать тексты в YAML. Схема ловит опечатки до того, как они попадут на сайт. |
| Фронтенд | **Vanilla ES-модули без сборщика** | Проект запускается одной командой `uv run horologium serve`, без Node.js. Библиотеки вендорены в `frontend/vendor/`. |
| 3D | **Three.js** | Глобус со спутниковой текстурой и процедурные 3D-часы с разборкой. |
| Анимации | **GSAP + ScrollTrigger, Lenis** | Скролл-сцены в стиле Apple, плавная прокрутка, переходы между страницами. |

## 3. Структура репозитория

```
content/                     ← ИСТОЧНИК ИСТИНЫ (YAML)
  countries.yaml             страны: центр камеры, города, факты, интро
  complications.yaml         словарь усложнений
  movements.yaml             общие калибры (ETA, Sellita, Miyota, Seiko NH…)
  brands/<country>/<brand>.yaml   бренд + его калибры + модели с render-спекой

backend/horologium/
  config.py                  пути и настройки (env HOROLOGIUM_*)
  content/schema.py          Pydantic-схема YAML (строгая, extra=forbid)
  content/loader.py          чтение, валидация, перекрёстные ссылки, digest
  db/models.py               ORM-модели SQLite
  db/build.py                YAML → SQLite (+ сохранение истории цен)
  db/base.py                 движок и сессии
  services/catalog.py        запросы и агрегаты (средняя цена, фасеты)
  services/search.py         поиск с транслитерацией и нечётким совпадением
  api/schemas.py             контракт ответов API
  api/routes.py              роуты /api/v1/*
  web/spa.py                 раздача фронтенда + SSR мета-тегов
  pricing/providers.py       извлечение цены из JSON-LD / meta, курсы ЕЦБ
  pricing/refresh.py         CLI обновления цен и отчёт о свежести
  cli.py                     `horologium serve|check|build-db|prices`
  main.py                    create_app()
backend/tests/               pytest

frontend/                    SPA без сборки (см. docs/DESIGN.md)
scripts/                     утилиты: загрузка ассетов, автокавычки YAML
data/                        SQLite (в .gitignore)
docs/                        документация
```

## 4. Поток данных

```
content/*.yaml ──(loader + schema)──▶ ContentBundle ──(db/build)──▶ SQLite
                                                                     │
          pricing/refresh ──▶ price_snapshots (переживает пересборку) ┘
                                                                     │
                     services/catalog ──▶ api/routes (/api/v1) ──▶ фронтенд
```

- При старте сервера `ensure_database()` сравнивает SHA-256 всего контента с `meta.content_digest`. Если контент изменился, каталог пересобирается автоматически.
- Таблица `price_snapshots` не удаляется при пересборке. Если обновлялка нашла цену новее, чем дата `checked` в YAML, в каталог попадает свежая цена.

## 5. API (v1)

| Метод | Описание |
|---|---|
| `GET /api/v1/stats` | счётчики каталога |
| `GET /api/v1/countries` | страны со статистикой цен |
| `GET /api/v1/countries/{slug}` | страна + бренды (средняя цена, мин/макс) |
| `GET /api/v1/brands?country=` | бренды |
| `GET /api/v1/brands/{slug}` | бренд, история, фасеты-вкладки, модели |
| `GET /api/v1/watches?brand=&country=&type=&complication=&sort=` | фильтр моделей |
| `GET /api/v1/watches/{slug}` | модель целиком: механизм, история, цена, соседи |
| `GET /api/v1/complications[/{slug}]` | словарь усложнений |
| `GET /api/v1/movements/{slug}` | калибр и часы с ним |
| `GET /api/v1/search?q=` | поиск |

Фасеты бренда: `all`, `mechanical` (автомат + ручной), типы механизмов (`automatic`, `manual`, `quartz`, `solar`, `spring_drive`, `smart`…), затем усложнения с `tab: true`.

## 6. Цены

- Каждая цена хранит `usd`, `kind` (`msrp` официальная розница / `market` рынок / `estimate` оценка), `source`, `url`, `checked`.
- Основной путь: исследование официальных прайс-листов (сайт бренда через реальный браузер, т.к. многие сайты закрыты антиботом для скриптов) и авторитетных сводок. Дата проверки указывается в YAML.
- Автоматическое обновление: `horologium prices refresh` проходит по моделям с `price.url`, пробует провайдеров (`JsonLdProvider`, `MetaTagProvider`), пересчитывает валюту по курсам ЕЦБ и пишет снимок. Сайты с Cloudflare-челленджем (например, Jomashop) честно пропускаются.
- Средняя цена бренда и диапазон (мин, макс) считаются по моделям бренда в атласе (`services/catalog.price_stats`).

## 7. SEO

SPA-шелл `frontend/index.html` содержит маркеры `<!--SSR:TITLE-->` и `<!--SSR:DESCRIPTION-->`, которые сервер заменяет на заголовок и описание страны, бренда или модели. Ссылки в мессенджерах и поисковиках получают правильные превью.

## 8. Тесты

`uv run pytest` собирает временную базу из настоящего контента и проверяет: валидность и хронологию контента, адекватность цен, агрегаты, фильтры, поиск, 404, SSR-мета.
