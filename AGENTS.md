# Памятка для ИИ-агентов

Прочитайте по порядку: `README.md` → `docs/ARCHITECTURE.md` → `docs/PROGRESS.md` (последний блок = текущее состояние) → `docs/CONTENT_GUIDE.md` или `docs/DESIGN.md` в зависимости от задачи.

## Правила проекта

- **Бэкенд только на Python** (FastAPI + SQLAlchemy + SQLite). Фронтенд без сборщика: ES-модули + import map, библиотеки лежат в `frontend/vendor/`.
- **Источник истины для контента: YAML в `content/`.** SQLite производная, её не редактируют руками и не коммитят. После правки YAML: `uv run horologium check`.
- **Цены** всегда с источником (`source`), датой проверки (`checked`) и типом (`msrp` = официальная розница, `market` = рынок/грей, `estimate` = оценка). Не выдумывайте цены: лучше `estimate` с пометкой.
- **Тексты на русском**, без длинного тире «—» в интерфейсе и контенте (стиль проекта): используйте точку, запятую или двоеточие. Двоеточие с пробелом внутри YAML-значения требует кавычек (`scripts/yaml_autoquote.py` делает это автоматически).
- **Логотипы брендов не используем**, только названия текстом (товарные знаки).
- После каждого законченного блока: `uv run pytest`, `node scripts/site_audit.mjs http://127.0.0.1:8765` (сервер запущен; должно быть «Чисто»), запись в `docs/PROGRESS.md`, коммит.
- **Анимации на canvas** (симуляторы) крутят кадры через `frameGate(el)` из `core/motion.js`: за экраном цикл спит. В `destroy()` вызывать `raf.stop()`.
- **Скорость на слабых ноутбуках.** Ничего тяжёлого «в фоне на всякий случай»: глобус, three.js, HDRI и сцены
  грузятся там, где нужны, и тогда, когда секция подходит к экрану. Бесконечных циклов кадров в покое нет
  (Lenis и тикер GSAP засыпают). Для слабых устройств облегчённые версии через `lowPower()`. После правок,
  влияющих на загрузку: `node scripts/perf_audit.mjs http://127.0.0.1:8765` и сравнить с прошлым замером.
- **Иконки**: новая иконка `ph-*` в коде требует `scripts/icons_subset.py` (иначе она невидима; тест ловит).
- **Фото моделей** в карточках и шапках: официальные студийные снимки брендов или свободные снимки с автором и лицензией. Сгенерированного 3D в справочных местах нет.
- **Разборка до детали** (`content/teardown/`, `scripts/teardown.py`, `docs/TEARDOWN_GEMINI_TASK.md`): детали генерирует Gemini 3 Pro Image по официальным фото, на сайте это подписано. Ключ Gemini только в переменной окружения `GEMINI_API_KEY`, в репозиторий не попадает. Исходные 4K-листы лежат в `teardown_src/` (в .gitignore).
- **Порядок работы с разборкой** (обязателен, в том числе для Antigravity/Gemini):
  1. Картинки в `~/Desktop/Horologium-детали/` под именами со страницы заданий; оригиналы не перезаписывать
     (увеличенные копии сохранять рядом или класть в `teardown_src/` через `import`).
  2. `uv run python scripts/teardown.py import`, затем `review <slug>`: открыть каждый лист и сверить
     подписи с деталями. Если Gemini сдвинул детали по клеткам, правка в `content/teardown/fixes.yaml`.
  3. `build <slug>`. Если напечатано «НАРЕЗКА ИСПОРЧЕНА», атлас не коммитить, разобраться.
  4. `sheet <slug>`: открыть лист всех вырезанных деталей и посмотреть глазами; детали должны быть
     целыми, без дыр и обрывков. Затем `node scripts/teardown_shots.mjs <url модели> <префикс>`: кадры
     3D-разборки (собраны, по оси, лоток). «Проверено» писать только после этого.
  5. Журнал: блок дописывается и в `docs/PROGRESS.md`, и в `Progress.md` (тест проверяет, что они совпадают).
- **Фильм-разборка в Blender** (`scripts/blender/`, `docs/ARCHITECTURE.md` §10): текстуры только из официальных
  снимков бренда, и то как маски; ничего не дорисовывать шрифтами. Если что-то скрыто на одном снимке, искать
  другой официальный (так печать под стрелками взята с голого циферблата raw-dial). Условность механизма
  подписывать в `content/teardown/films.yaml` (`note`). Проверять кадры глазами до полного рендера.

## Мастерская Submariner и дизайн

- `/watch/rolex-submariner#explode`: самостоятельная GLB-мастерская. Сначала прочитайте
  `docs/SUBMARINER_WORKSHOP.md`. Для остальных моделей: `docs/CATALOGUE_WORKSHOPS.md`, готовые GLB и общий интерфейс.
  Новую модель добавлять вместе с экспортом и проверкой покрытия. Не подменять справочные фото 3D.
- Для интерфейса доступны официальные Taste (`.agents/skills/design-taste-frontend/SKILL.md`) и
  Impeccable (`.agents/skills/impeccable/SKILL.md`). Контекст продукта в `docs/PRODUCT.md`,
  действующая визуальная система в `docs/DESIGN.md`. Кеш Impeccable: `sh scripts/design_tools.sh`.
- После изменения мастерской: дополнительно `node scripts/submariner_audit.mjs <url>`.
  Проверять изображения, выбор геометрии, описания, сборку, 390/768/1440 px, reduced-motion,
  Save-Data и остановку кадров в покое. Бюджет GLB проверяет `test_assets.py`.

- После изменения общих мастерских: также `node scripts/catalogue_workshops_audit.mjs <url>`.
  Проверять все GLB, архитектуру механизмов, отдельные детали, обратную сборку, мобильный экран,
  темы, Save-Data и освобождение сцены. Исходный Submariner не регенерировать общей фабрикой.
